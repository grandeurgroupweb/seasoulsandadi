# Sitemap — Sea Soul Sandadi

One public page with section anchors, plus an auth-gated admin area. Anchor IDs and routes below are canonical: components, nav links and tests use exactly these.

```
/                          public landing page (indexed)
├── #top                   Hero (scroll-zoom: venue layout → live photos)
├── #experience            The Experience (6 category chips + photos)
├── #edition               This Month's Edition (date / venue)
├── #gallery               Event Gallery (auto-scroll carousel)
├── #vendors               Be a Part of Sea Soul Sandadi (WhatsApp CTA)
├── #reels                 From Our Instagram (reel cards marquee)
├── #faq                   Frequently Asked Questions
└── #contact               Follow Us + footer

/admin                     → redirects to /admin/gallery      (auth, noindex)
├── /admin/login           email + password sign-in            (public, noindex)
├── /admin/gallery         upload / categorize / reorder / delete images
├── /admin/edition         current edition: date, venue, "announcing soon"
├── /admin/faq             add / edit / reorder / delete FAQs
├── /admin/content         editable page copy (site_content)
└── /admin/settings        WhatsApp number + message, social links, contact

/robots.txt                generated by src/app/robots.ts
/sitemap.xml               generated by src/app/sitemap.ts (lists only /)
```

Nav order: Home · Experience · This Edition · Gallery · Vendors · FAQ · Contact. No "Book Tickets" item.

Notes:
- `#top` is the `id` on the hero `<section>`; the logo also links to `/#top`.
- Sections use `scroll-margin-top` equal to the sticky header height so anchored headings aren't hidden under it.
- Footer quick links repeat the nav anchors.
- Experience chips scroll to `/#experience-<category-slug>` (e.g. `#experience-pets`), one sub-anchor per category block inside the section. Slugs: `flea-market`, `food`, `music-dance`, `pets`, `workshops`, `photo-moments`.
- Anchors are not separate URLs for search engines; only `/` is in the sitemap.

## Admin routes

| Route | Access | Indexing | Purpose |
| --- | --- | --- | --- |
| `/admin/login` | Public (signed-in users are redirected to `/admin/gallery`) | `noindex, nofollow` | Supabase email + password sign-in |
| `/admin` | Admin only | `noindex` | Redirects to `/admin/gallery` |
| `/admin/gallery` | Admin only | `noindex` | `gallery_images` CRUD, uploads to `media` bucket |
| `/admin/edition` | Admin only | `noindex` | Edit the single `editions` row (`id = 1`) |
| `/admin/faq` | Admin only | `noindex` | `faqs` CRUD + order |
| `/admin/content` | Admin only | `noindex` | `site_content` key/value copy |
| `/admin/settings` | Admin only | `noindex` | Single `site_settings` row (`id = 1`) |

Access control, in layers (see `SECURITY.md`):
1. `src/proxy.ts` refreshes the Supabase session and redirects unauthenticated `/admin/*` requests (except `/admin/login`) to `/admin/login`.
2. `src/app/admin/(protected)/layout.tsx` re-checks the user and `is_admin()` on the server.
3. Supabase RLS rejects every write unless `is_admin()` is true. This is the real guard.

Signed-in non-admin users (if public sign-up were ever enabled by mistake) see an "access denied" screen, not the admin UI.

## If this ever becomes multi-page

Likely candidates: `/vendors` (vendor info and past brands), `/editions/<slug>` (past edition recaps, would need edition history in the DB), `/gallery` (full archive). Each would need its own metadata, an entry in `sitemap.ts`, nav links changed from anchors to routes, and Event JSON-LD moved to the edition page. Not in scope now.
